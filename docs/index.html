Building a CBM article page

What the converter hands you, how to put it on the site, and what every part of the markup is for.

Matches converter 1.5.1 Updated 06 October 2026 Releases

Pull quotes, working

The article carries its own styling, so this needs nothing set up on the site. Below 900 pixels the quotes stop floating and become centred blocks.

Baptism is not the final step of salvation.

Second, baptism is not the final step of salvation. If it were, the thief on the cross could have had no hope, and Paul would not have thanked God that he baptised so few at Corinth. The Reformers returned to this point repeatedly, because the alternative makes the sacrament the thing that saves.

The quotes alternate down the article: the first sits left, the next right, and so on. That is worked out in reading order, so inserting one in the middle renumbers the rest by itself.

What the editors send you

Two files per article, holding exactly the same thing, named with the date and time of conversion.

  • The .html is for looking at in a browser, to check the article works.
  • The .txt is for copying the code. It opens in Notepad.

Both begin with the title and author as plain text, above a marked line:

TITLE
Water Baptism’s True Role in the Gospel

AUTHOR
Aleksander Gurtaev

----- paste everything below this line into the Code Block -----

Those two are for Squarespace’s own title and author fields. They sit above the line so they cannot be pasted into the article by accident.

Putting it on the site

  1. Open the .txt. Cut the title and the author from above the marked line and paste them into Squarespace’s own fields.
  2. Select everything below the marked line and copy it.
  3. Add a Code Block. Not a Text Block — a Text Block strips the id attributes the footnotes depend on, and every footnote link stops working.
  4. Delete the placeholder content, paste, and check the block is set to HTML with “Display Source” unticked.
  5. Save and look at the published page. Code Blocks often do not render inside the editor, so the editor preview proves nothing.
  6. Click a few footnotes on the live page: the raised number should jump down, and the number at the foot should jump back.

If the article has photographs, they are not in the code. Place them as ordinary Image Blocks and split the text into two Code Blocks around each one. Footnote links still work across blocks, because it is all one page.

Every element, and what it is for

The rendering on the left is produced by the code on the right.

Blurb

Opens the article, set larger than the body. Comes from the Blurb style in Word.

Russian evangelicalism developed under the influence of Orthodoxy rather than the Reformation.

<p class="cbm-blurb">Russian evangelicalism developed under the influence of Orthodoxy rather than the Reformation.</p>

Reading time

Counted from the body at 200 words a minute. The clock is drawn in the page, not an image file.

27 min read

<p class="cbm-read"><svg class="cbm-clock" viewBox="0 0 16 16" fill="none" stroke="currentColor" stroke-width="1.5" aria-hidden="true"><circle cx="8" cy="8" r="6.4"/><path d="M8 4.3V8.2l2.5 1.5" stroke-linecap="round" stroke-linejoin="round"/></svg>27 min read</p>

Section heading

Always h2 for top-level sections. There is no h1: Squarespace supplies the page title.

Baptism and the Gospel

<h2>Baptism and the Gospel</h2>

Body text

No class and no styling, so it inherits whatever Paragraph 2 is set to in Site Styles.

The Protestant Reformation spawned a multitude of disagreements about the doctrine of water baptism.

<p>The Protestant Reformation spawned a multitude of disagreements about the doctrine of water baptism.</p>

Block quotation

A quotation from another source. Styled by your theme, not by the article.

We do not become members of Christ’s body by the act of baptism.

<blockquote><p>We do not become members of Christ’s body by the act of baptism.</p></blockquote>

Verse

Scripture or poetry. One paragraph per stanza, lines separated by br, with a hanging indent.

The LORD is my shepherd;
I shall not want.

<p class="cbm-verse">The LORD is my shepherd;<br/>I shall not want.</p>

Hebrew

A paragraph that is mostly Hebrew is marked right to left. Greek is tagged but not reversed.

שְׁמַע יִשְׂרָאֵל

<p lang="he" dir="rtl">שְׁמַע יִשְׂרָאֵל</p>

Author bio

Moved to the end of the article, above the footnotes.

Alex is the dean and New Testament Chair at Samara Center for Biblical Training.

<p class="cbm-bio">Alex is the dean and New Testament Chair at Samara Center for Biblical Training.</p>

Footnotes

The number at the foot links back to the callout. This is why it must be a Code Block: a Text Block strips the id attributes and every link dies.

A sentence with a note.1

  1. 1. See Jonathan H. Rainbow, Confessor Baptism, 189–92.

<p>A sentence with a note.<sup><a href="#demo-fn1" id="demo-ref1">1</a></sup></p>
<ol class="cbm-footnotes"><li id="demo-fn1"><p><a href="#demo-ref1" class="footnote-back">1.</a>&#160;See Jonathan H. Rainbow, <em>Confessor Baptism</em>, 189–92.</p></li></ol>

Photographs

Pictures do not arrive inside the code. Each is saved to a folder beside the article, and the article carries a marked block where it belongs:

<figure class="cbm-figure cbm-figure-right" style="width:40%">
  <div class="cbm-image-missing">PICTURE GOES HERE …</div>
  <figcaption>…</figcaption>
</figure>

Upload the pictures to the site, then in the converter use Designer › Place the pictures and paste each address. It returns a copy of the article with the real pictures in place, each with a srcset so the browser takes a size that suits the screen.

The width on the figure is the one piece of styling that is not in the stylesheet, because it belongs to that single photograph — it is how large the picture is shown in the Word document, as a share of the text column.

If a marked block reaches a published page, a picture was missed. It is designed to be conspicuous for exactly that reason.

The stylesheet

Articles no longer carry their own styling. It lives in Custom CSS, so one edit reaches every article on the site, including ones published long ago. Get it from the converter: Designer › Copy the article stylesheet, then paste it into Design › Custom CSS.

The block is marked BEGIN and END. Anything you write outside those lines is yours and survives a fresh paste. When the converter changes a class, the release notes say so.

Hebrew

Squarespace sets the body font through a variable rather than by name, so adding a Hebrew face has to go through that variable. Competing on font-family loses: their selector is more specific.

@font-face {
  font-family: 'CBMHebrew';
  font-style: normal;
  font-weight: 100 900;
  font-display: swap;
  src: url(THE_UPLOADED_FONT_URL) format('woff2');
  unicode-range: U+0590-05FF, U+FB1D-FB4F, U+200F, U+200E;
}

:root, body {
  --body-font-font-family: 'CBMHebrew', 'tinos-h4tbxy', serif;
}

[lang="he"], [lang="he"] * {
  --body-font-font-family: 'CBMHebrew', 'tinos-h4tbxy', serif;
}

The unicode-range is what makes this safe: only Hebrew characters use that face, Latin is untouched even in the same sentence, and the font is not downloaded on pages with no Hebrew.

The name tinos-h4tbxy is Squarespace’s own label for the uploaded body font. Change the body font in Site Styles and that name changes, at which point Latin inside Hebrew elements falls back to a plain serif. The Hebrew itself keeps working. Update both places above if the body font is ever changed.

The one thing to set up once

Everything above works with no site-wide setup. Hebrew is the exception: the site font does not position Hebrew vowel points correctly, so a Hebrew face has to be added under the same family name, scoped to the Hebrew range.

Upload the font through Manage Custom Files in Design › Custom CSS, then add this below whatever declares the site font. Put the cursor between the brackets of url() and click the uploaded file to insert its address.

@font-face {
  font-family: 'Tinos';
  src: url();
  unicode-range: U+0590-05FF, U+FB1D-FB4F, U+200F;
}

Latin text is untouched, and the Hebrew font is only downloaded on pages that contain Hebrew.

If something looks wrong

Footnotes do nothing on the published page
A Text Block was used instead of a Code Block.
The share icons do nothing
The short script at the very end of the file was not included in the paste. Copy everything, including what comes after the last paragraph.
Pull quotes sit centred on a wide screen
The article’s own style block was not pasted, or something on the page is overriding it. The styling is near the top of the pasted code, inside a style tag.
Hebrew letters and vowel points do not line up
The font setup above has not been added, or it sits above the rule that declares the site font instead of below it.
You need to know which version produced an article
Every file begins with a hidden comment naming it. It never shows on the page and survives into the Code Block.
